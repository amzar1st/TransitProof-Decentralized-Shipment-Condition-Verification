# Studio walkthrough

1. Import `contracts/transit_proof.py` in https://studio.genlayer.com/contracts. Use Normal (Full Consensus), and deploy with no arguments. The selected built-in account becomes shipper/deployer. No wallet extension is required.
2. Copy the addresses of two other built-in accounts for carrier and recipient. For a solo test you may use the deployer's address in every role, but label it a single-signer demo.
3. Prepare dispatch/arrival JPEG or PNG files using `examples/prepare_photos.py`. Display the serial number clearly in both photographs along with packaging and equipment. For a damaged case, show the damaged area at arrival. Do not use the test fixture bytes as real images.
4. As shipper, call `register_shipment` with `shipment_id="TP-DEMO-001"`, carrier/recipient addresses, `serial_number="TP-SN-001"`, the dispatch SHA-256, `handling_requirements="Keep dry; keep packaging intact; protect from visible impact damage"`, a future Unix-seconds `delivery_deadline` (e.g. now + 3600), `inspection_seconds=60`, `review_seconds=60`.
5. As shipper, `record_checkpoint("DISPATCH", dispatch_sha256, "Released sealed item to carrier")`.
6. Switch built-in account to carrier. Call `acknowledge_checkpoint()` and then `record_checkpoint("ARRIVAL", arrival_sha256, "Presented item to recipient")`.
7. Switch to recipient. Call `acknowledge_checkpoint()`, starting the 60-second inspection clock. Submit `submit_delivery(arrival_sha256, "Received and photographed for inspection")` before it expires. Optionally call `raise_dispute("Visible packaging damage", arrival_sha256)` in that window.
8. After `inspection_deadline` (from `get_shipment`) has passed, any shipment party calls `verify_delivery(dispatch_photo_base64, arrival_photo_base64)` with the strings generated by the helper. Both must decode to exactly the committed bytes. Wait for successful transaction execution; inspect node logs for model/consensus errors.
9. Read `get_shipment()`. Inspect each PASS/FAIL/UNKNOWN observation, the derived verdict, immutable commitments and custody signers. If a model lacks visual support or independent validators disagree, do not claim success; retain the error and retry only with the same committed evidence.
10. After `assessment.finalize_after`, call `finalize_delivery()`. Read again and verify `state="FINALIZED"`. Separately confirm protocol finality of all relevant transactions; the contract's delay is not the network appeal window.

## Alternate demonstrations

- **Item mismatch:** use a clearly different arrival serial. Expect `ITEM_MISMATCH` if independently agreed.
- **Insufficient evidence:** obscure the serial or item condition. Expect `INCONCLUSIVE` if no definitive failure is established.
- **Missing receipt:** deploy a fresh instance with short deadlines and no delivery submission. After the relevant deadline, permissionless `finalize_delivery()` yields `INCONCLUSIVE`.
- **Tampering:** change photo bytes after the checkpoint hash is signed. Verification rejects before any LLM call.

Photo contents, handling text and receipt notes never authorize changes to output schema or contract state. The fixed result fields and deterministic mapping are enforced by code.
